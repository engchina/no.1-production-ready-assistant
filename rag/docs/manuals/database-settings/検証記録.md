# データベース設定の検証記録

> **後の画面の変更**: 以下は撮影時の画面と実装の記録です。ADB の運用パネル（状態表示・「情報を再取得」）は #10 で、OCI からの Wallet の自動取得（`ensureWalletFromOci()`）は #11 で削除しました。記事の本文は今の画面に合わせています。

## 確認日と対象

- 確認日：2026年10月28日（日本時間）。
- 対象：RAG の「システム設定 → データベース」。
- Desktop：1440 × 1080。狭い画面：375 × 812。
- 専用の Chromium セッションで、利用者が指定した環境にログインして確認。環境 URL、アカウント、パスワードは成果物へ記載していない。

## 実画面で確認した操作

| 操作 | 結果 |
|---|---|
| システム設定を展開してデータベースへ移動 | 「データベース設定」「Autonomous Database 管理」を表示 |
| ADB の状態表示 | 「OCI ADB: 起動済み」を表示。起動・停止は行っていない |
| 既存設定を変更せず DB接続テスト | Desktop と375pxで成功。APIの結果は両方 `success`、画面文言は「Oracle AI Database への接続に成功しました。」 |
| データベースユーザーを半角スペース3文字にして DB接続テスト | 「データベースユーザーを入力してください。」。この入力操作で接続テスト API の追加送信はない |
| 合成ファイル「架空サンプル_形式確認用.txt」をファイル入力へ選択 | 「このファイル形式は使用できません。.ZIP ファイルを選択してください。」。アップロード要求はない |
| 375px の入力エラー表示 | 必須入力とファイル形式の両エラーを表示。ページ全体の横方向のはみ出しなし |
| 終了処理 | ログアウト操作、ブラウザーの Cookie 削除、専用 Chromium プロセスの終了 |

非対応の `.txt` は Playwright のファイル選択で指定した。OS のファイル選択ダイアログ自体は撮影・検証していない。環境によってはダイアログの拡張子フィルターを解除する必要がある。

画面を開く操作と接続テストは実サービスを使用し、API の応答を模造していない。入力チェックの確認後はページを再読み込みし、未保存の入力を破棄した。

## 既存環境を保護するための制限

ブラウザー側で `/api/settings/` 以下の GET 以外を予防的に遮断した。ただし副作用を実装照合した `/database/test` の POST は許可した。設定の更新、Wallet アップロード・取得、ADB 起動・停止、表の初期化等はこの許可に含まない。

- 予防遮断に該当した要求：**0件**。遮断によるエラーを製品の実際の動作として記事には記載していない。
- 実際に送信された DB 接続テスト：**2件、いずれも成功**。
- 新規ユーザー、DB ユーザー、DB データは作成していない。
- 設定の保存、Wallet の差し替え・再取得、ADB の起動・停止、パスワード表示・削除、表の初期化は未実施。
- 初回の Wallet 自動取得も発生していない。既存 Wallet が設定済みだった。

## 実装と照合した事項

参照した実装：

- `platform/packages/system-settings/src/database/DatabaseSettingsPage.tsx`
- `platform/packages/system-settings/src/database/messages.ts`
- `platform/packages/system-settings/src/database/hooks.ts`
- `platform/packages/system_settings_backend/src/pr_system_settings/database.py`
- `rag/backend/app/api/routes/settings.py`
- `rag/backend/app/clients/oracle.py`
- `rag/backend/app/security/permissions.py`

| 事項 | 根拠 |
|---|---|
| メニューとAPIに `menu.settings_database` が必要 | RAG の permission manifest |
| 共通のDB設定を利用 | 共通画面・API、および `docs/agents/shared-features.md` |
| 接続テストは未保存の入力を候補設定へ適用 | `runTest` → `payloadFromForm` → `database_settings_candidate` |
| DB接続テストにschema初期化がない | RAG の `test_oracle_connection` → `_test_oracle_connection_sync`。接続して `SELECT 1 FROM DUAL`、結果1行取得、カーソルと接続を閉じる |
| 空欄のパスワードは既存値を保持 | `secret_value` による候補設定作成、フォームの helper 文言 |
| ADB OCID は読み取り専用 | `adb-ocid` の `readOnly` |
| 「情報を再取得」とADB管理の「保存」に副作用がある | `handleRefresh` が `persist()` のあと `ensureWalletFromOci()` を呼ぶ。後者は Wallet ダウンロード・サーバー設定へ進む |
| Wallet未設定時の自動取得 | `useEffect` が Wallet 未設定・ADB OCIDあり・Wallet mTLS の条件で取得を開始 |
| Walletの選択は即時処理 | `WalletUploadField` の `onFiles` → `uploadWallet` → `walletUpload.mutate` |
| DB保存の通知 | 保存成功時の `settings.database.actions.saved` は「保存しました」 |

保存・正しい Wallet ZIP のアップロードと内容検査、Wallet再取得、起動・停止、接続障害の再現は未実施。これらは実装に基づく説明と、実測した結果を記事内で分けている。
