# Production Ready RAG のアップロード保存先を使ってみる

> **注意（#11 / #51）**: OCI Object Storage の保存先・「接続を確認」・「OCI 認証設定」の画面は #11 で削除しました。今の画面は、原本を保管するローカルのディレクトリ（「ローカル保存ディレクトリ」）を入力して保存するだけです。この記事は今の画面に合わせて書き直し、削除した機能の節と図は外しました（#51）。残した図 2 枚は削除前の画面で撮影したもので、図2には今の画面に無い保存先の種類の選択（「OCI Object Storage」）が写っています。撮り直しは別の Issue で行います。

## はじめに

RAG にアップロードした PDF・画像・テキストなどの**原本ファイル**を、どこへ保存するかを設定する画面です。保存先は、バックエンドが稼働する環境のディレクトリ（`PLATFORM_LOCAL_STORAGE_DIR`）です。

この記事では、入力する項目、保存の確かめ方、未保存の入力の扱いを確認します。

> **確認範囲**
>
> 2026年10月28日に実画面で、ローカル保存ディレクトリへの日本語の合成値の未保存入力と、変更破棄の確認を操作しました（#11 の削除の前の画面）。今の画面の文言と動作は、platform の共有パッケージの実装と e2e テスト（`rag/frontend/e2e/upload-storage-settings.spec.ts`）で照合しています。
>
> 既存設定を保護するため、保存先の変更を保存していません。保存の成功通知などは実装を確認した説明です。画像は実画面の機密情報を黒塗りし、重要な箇所に赤枠と番号を加えています。

## 前提条件

- RAG にログインし、「システム設定 → アップロード保存先」を開けること。必要なメニュー権限は `menu.settings_upload_storage` です。
- バックエンドの実行ユーザーが作成・書き込みできるディレクトリを、環境管理者が準備していること。
- 新しい保存先を試す場合は、既存の運用に影響しない検証環境を用意すること。

**バックエンド**は RAG の処理を実行するサーバー側のプログラムです。ここでいう「ローカル」は、ブラウザーを開いている手元のパソコンではなく、そのバックエンドの実行環境を指します。

保存先の設定は共通の設定ファイルへ保存されます。同じ環境の他の製品にも影響するため、確認だけのつもりで運用中の保存先を変更しないでください。

## 今回使うサンプル

[サンプルの説明](samples/README.md)から、次の日本語ファイルを開けます。実在する人物・顧客・組織や既存の業務データは使っていません。

| ファイル | 用途 |
|---|---|
| [入力例.json](samples/入力例.json) | 架空のローカル保存パス。画面へ手入力して使用 |
| [架空サンプル_原本保存確認.txt](samples/架空サンプル_原本保存確認.txt) | 保存先設定後の確認に利用できる合成のテキスト原本。今回はアップロードしていない |

この画面には、JSON や原本文書をアップロードする欄はありません。ここで保管場所を設定し、文書自体のアップロードは別の「文書アップロード」で行います。

## 操作手順

### 1. 「アップロード保存先」を開く

1. 左のナビゲーションで **システム設定** を開きます。
2. **アップロード保存先** を選びます。
3. 見出しに **アップロード保存先**、画面内に **保存先** と表示されることを確認します。

### 2. ローカル保存ディレクトリを入力して保存する

1. **ローカル保存ディレクトリ** に、環境管理者が準備した保存先を入力します。
2. 入力内容を確認して、**保存** を押します。
3. 保存成功時の通知 **保存しました** を確認し、再表示したときも設定が残っていることを確かめます。

欄が空のまま保存すると、**ローカル保存ディレクトリを入力してください。** と表示され、保存されません。

次の図では、入力例として `/検証用/架空サンプル/原本保存` を入力しました。これは架空の説明用パスです。実際にディレクトリを作成したり、設定を保存したりはしていません。

![ローカル保存ディレクトリへ日本語の架空パスを入力した実画面。入力欄と保存ボタンを番号付きの赤枠で示す。#11 の削除の前の画面のため、保存先の種類の選択が写っている](images/02-ローカル保存先の入力例.png)

*図1：①へ保存パスを入力し、設定を変更する場合に②で保存します。今回実際に確認したのは①の未保存入力までです。図の上部の保存先の種類の選択（ローカルディレクトリ / OCI Object Storage）は削除前の画面のもので、今の画面にはありません。*

この画面に「接続を確認」ボタンはありません。保存できたことと、実際に原本を書き込めることは別に確認してください（文書アップロードの後に原本を表示できるか）。

### 3. 検証用の入力を保存せず破棄する

1. 保存しない場合は、左のナビゲーションなどで別の画面を選びます。
2. **変更を破棄しますか** と表示されたら、意図に合う操作を選びます。
3. 入力を見直す場合は **キャンセル**、保存せず移動する場合は **破棄して移動** です。

![未保存の変更を破棄するかを確認する実画面。キャンセルと破棄して移動の選択肢を赤枠と番号で示す](images/06-変更破棄の確認.png)

*図2：①「キャンセル」は編集画面へ戻る操作、②「破棄して移動」は変更を保存せず移動する操作です。今回はダイアログの表示とキャンセルを確認し、その後、再読込みで合成入力を破棄しました。②の押下は未実施です。*

## まとめ

「アップロード保存先」では、原本を保存するサーバー側のディレクトリを指定します。**入力 → 保存 → 再表示と原本保存の確認** の順に進めます。

入力だけでは設定は保存されません。保存の通知だけで判断せず、実際に文書をアップロードして原本を保存できるかも確かめてください。

詳しい確認範囲と未実施事項は[検証記録](検証記録.md)に記載しています。
