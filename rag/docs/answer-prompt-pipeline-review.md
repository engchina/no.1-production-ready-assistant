# 回答プロンプトの処理順と機能変更の照合

## 対象と方法

2026-09-21 以降、基点 `7d73b0479c` までの RAG の変更履歴を対象に、回答プロンプト画面の全 22 段と編集できる 2 テンプレートを照合した。RAG に関係する非 merge commit は 1,313 件、各段の本文と呼び出し元に関係する履歴は 233 件。履歴から影響する機能を抽出し、現行の入力、応答 schema、呼び出し条件、実行順を確かめた。実モデルでの回答品質の比較は、このコードと表示の照合とは別の検証であり、今回は実施していない。

正本は [段の定義](../backend/app/rag/answer_prompts.py)、[取込](../backend/app/rag/ingestion.py)、[検索の入口](../backend/app/rag/pipeline.py)、[回答フロー](../packages/rag_engine/rag_engine/generation/answering.py)、[評価](../packages/rag_engine/rag_engine/evaluation/answer_eval.py)。画面はこの段の順を維持し、各区分の説明で独立した準備・分岐・反復を示す。

## 表示順

1. 文書解析: Dots.OCR → 図・画像 → 見出しの階層 → 項目抽出 → 章節の要約。
2. 文書分割・索引: 分割後の RAPTOR 要約。
3. 業務ガイドの準備: 回答の過程からの下書き。文書の取込とは独立。
4. 質問の解釈: ガイドの自由入力条件 → 会話の書き換え → 抽出項目の検索条件 → 戦略選択 → 検索文の追加。
5. 検索: 画面の目録 → 条の目録。条は文書選択 → 条選択 → 同じ章と名指しの条の追加選択。
6. 根拠の判定・補完: CRAG の判定と、長い章節の原文抽出。再検索・拡張に伴う反復がある。
7. 回答の生成: FAQ の別経路、根拠による生成の system 指示 → 編集可能な入力テンプレート。
8. 監査: 有効時の生成後の監査 → 補助の規則の当てはめとその監査。
9. 評価: 範囲の固定 → 網羅性・忠実性 → 正確性。MCP の資料との照合は独立した呼び出し。

[設定の概要](../frontend/src/components/settings/PipelineHubClient.tsx)の取込 → 検索・回答 → 評価に沿い、取込内は同じ[レシピの項目順](../frontend/src/components/documents/DocumentProcessingConfigPanel.logic.ts)を使う。ファイル準備・通常の分割・埋め込み・文書構造索引の構築・OCI Guardrails は LLM 指示を持たないため、架空のプロンプトを追加しない。図の先読みは解析と並行し得る。FAQ は通常の生成・監査と直列には実行しない。

## 編集できるテンプレート

回答テンプレートは、質問・根拠・原画像の対応を現行の `question`・`answer_context`・`evidence_metadata` で渡している。外部文書は生成時に `BEGIN_UNTRUSTED_RETRIEVED_CONTEXT` で囲み、文書由来の境界表記も無害化する。六指標の評価は回答生成の後の独立処理なので、標準回答や評価用の期待を回答テンプレートへ追加しない。

画像テンプレートも現行の抽出 schema と一致する。独自の保存値を勝手に書き換えず、取込と同じ `refine_image_retrieval_prompt` の結果を一覧で確認できるようにする。編集の保存先と適用範囲は変更しない。

## 検証の境界

表示の順序・条件、現在のテンプレートの反映、保存と取消、Markdown 原文、desktop / 375px を回帰テストで確かめる。引用は既存の行指定・原文復元・回答生成の隔離テストで検証する。実モデルの品質改善や稼働中サービスの反映を、これらのテストの成功から推測しない。
