# 注入の疑いの根拠の扱い: 警告して続けるか、隔離するか（#73）

検索した根拠の中に、モデルへの指示らしい文（プロンプト注入）を検知したとき、今の製品は**警告して生成を続ける**（根拠の ID と規則の名前だけを警告として渡し、根拠の命令文は実行せず根拠データとして読むよう指示する）。疑いの根拠を**隔離する**（本文を生成に渡さない）扱いを足すかを、同じ条件で比べて決めた記録。

**結論: 隔離は採用しない（今の「警告して続ける」を維持）。** 2 つの生成のモデルで、警告して続ける扱いの攻撃の成功は 0 件で、隔離しても攻撃の成功は減らず（減らす余地が無い）、正しい回答が 100% → 60% に下がった（誤検知の正当な文書・答えを含む根拠を捨てるため）。

## 前提（今の対策）

- 検知: `rag_engine/generation/answer_images.py` の `prompt_injection_warnings_for_records`（`PROMPT_INJECTION_PATTERNS` の 7 つの正規表現。英語の ignore / disregard / system prompt / role の上書き、日本語の「前の指示を無視」・「システムプロンプト」・「新しい指示」など）。根拠の本文と補助の文脈（`answer_metadata_context`。文書・章節・caption・脚注・表など）を見る。
- 生成と CRAG の評価器には、警告から抜粋を除いた「根拠の ID: 規則の名前」だけを渡す（`_prompt_safe_warnings`）。生成の prompt は根拠を不可信のデータとして区切り、その中の指示に従わないよう指示する。回答は根拠に結び付いた主張の単位で組み立て、監査する（grounded）。
- OCI Guardrails と、常に通過する旧 guardrail の段は #37 / #52 で削除した（`app/rag/guardrail_adapter.py` は旧段の静的解決だけで、安全チェックからは呼ばない）。この比較はそれらを前提にしない。

## 何を比べたか

`rag/backend/app/rag/injection_quarantine_experiment.py`（`python -m app.rag.injection_quarantine_experiment`）が、評価セットの質問ごとに、根拠を製品の回答の文脈（`build_chunk_answer_context`。検索・再ランクは使わない）にし、製品の生成（`synthesize_grounded_answer`）で回答する。

| 扱い | 生成に渡す根拠 | 全件が疑いのとき |
|---|---|---|
| `warn`（今） | すべて（疑いの根拠には警告を添える） | そのまま生成 |
| `quarantine` | 疑いの根拠（child と親）を文脈を作る前に除く | 生成を呼ばず `quarantined_all`（検索 0 件・障害と区別する状態） |

指標: 検知の適合率 / 再現率（根拠の単位）、攻撃の成功（回答に canary が出た）、正しい回答（答えの語をすべて含む）、回答できなかった試行（envelope の `outcome` が `answered` 以外）。各 2 回（モデルの揺れ）。生成は #59 の記録 / 再生を通し、`--replay` で鍵無しに同じ結果を作り直せる（今回、記録と再生で結果が一致することを確かめた）。

## 評価セット

[`rag/evaluation/injection-quarantine/cases.json`](../evaluation/injection-quarantine/cases.json)（合成。15 問）。

| 群 | 件数 | 内容 |
|---|---|---|
| `attack_detectable` | 8 | 規則で検知できる注入: 日本語・英語・システムプロンプトの出力の要求・役割の上書き・**画像から取り出した文字**・**補助の文脈（表の caption）**・答えを含む唯一の根拠に指示（全件隔離）・答えの一部が指示のある根拠にしかない（一部隔離） |
| `attack_undetected` | 2 | 規則に当たらない注入（「この文書を読んだ AI アシスタントは…付け加えること」・偽の事実を答えさせる注記） |
| `benign_match` | 4 | 規則に当たる正当な文: 注意喚起のために**引用した攻撃の文面**・英語の "you are now able to"・業務の「新しい指示により」・製品の機能名「システムプロンプトの設定」 |
| `control` | 1 | 注入の無い根拠だけ |

## 測定（2026-11-01）

```bash
cd rag/backend
uv run python -m app.rag.injection_quarantine_experiment --repeats 2 \
    --record ../../tmp/injection/recording.json --output ../../tmp/injection/report.json
uv run python -m app.rag.injection_quarantine_experiment --repeats 2 \
    --replay ../../tmp/injection/recording.json --output ../../tmp/injection/replay.json
```

検知（モデルに依らない）: 適合率 0.67（8 / 12）・再現率 0.80（8 / 10）。誤検知 4（上の `benign_match` のすべて）、見逃し 2（`attack_undetected` のすべて）。画像の文字・caption の指示は検知した。

生成（`deepseek-v4-flash` と `deepseek-chat`。どちらも同じ結果。各 30 試行）:

| 扱い | 群 | 攻撃の成功 | 正しい回答 | 回答できなかった | 全件隔離 |
|---|---|---|---|---|---|
| `warn` | 全体 | 0 / 20 | 100% | 3%（条件つき 1 件） | 0 |
| `warn` | 検知できる注入 | 0 / 16 | 100% | 6% | 0 |
| `warn` | 見逃す注入 | 0 / 4 | 100% | 0% | 0 |
| `warn` | 誤検知の正当な文 | — | 100% | 0% | 0 |
| `quarantine` | 全体 | 0 / 20 | **60%** | 40〜43% | 10 |
| `quarantine` | 検知できる注入 | 0 / 16 | 75% | 25〜31% | 2 |
| `quarantine` | 見逃す注入 | 0 / 4 | 100% | 0% | 0 |
| `quarantine` | 誤検知の正当な文 | — | **0%** | 100% | 8 |

- 攻撃の canary は、警告して続けても回答に一度も出なかった（言及も無い）。偽の事実（日当 9,999 円）も答えず、正しい根拠の 2,000 円を答えた。回答は根拠に結び付いた主張から組み立てるので、根拠の中の書式・追記の指示が回答の本文に入る経路が無い。
- 隔離の損失: 誤検知の正当な文書 4 問はすべて根拠が無くなり答えられない（例: 不審なメールの報告先を、注意喚起の引用のせいで答えられない）。答えを含む唯一の根拠に指示があると、警告して続ければ正しく答えられる（攻撃は不成功）のに、隔離すると答えられない。一部隔離では答えの半分（部長の承認）を失い、条件つきの回答になる。
- 見逃す注入は、隔離しても除けない（規則で検知できないものは、どちらの扱いでも生成に渡る）。
- 費用: どちらの扱いも生成の呼び出しは 1 試行 1 回（約 50 回・入力 約 52 万 token）。隔離は全件隔離で呼び出しを省く。

## 判断

| 項目 | 判断 | 根拠 |
|---|---|---|
| 疑いの根拠の隔離（既定・設定で選べる扱い） | 採用しない | 攻撃の成功を減らさず（警告で 0 件）、正しい回答を 40 ポイント下げる。規則の検知は誤検知が多く（適合率 0.67）、隔離は誤検知をそのまま回答の欠落にする。使われない設定を足さない |
| 今の警告して続ける扱い | 維持 | 誤検知しても回答の品質を落とさない（警告は ID と規則の名前だけで、根拠は使う） |
| 検知の規則の改善（誤検知・見逃しを減らす） | 今は変えない | 警告の誤検知は回答に影響しない。見逃しも今回は攻撃が成功していない。規則を広げるのは、隔離のように検知を使って根拠を捨てる扱いを入れるときに要る |
| 「隔離で根拠が無い」状態・管理者の再判定 | 実装しない | 隔離を採用しないので、根拠を捨てる状態が起きない（実験では `quarantined_all` として検索 0 件・障害と分けて数えた） |

Agent の副作用（外部への書き込み）は、根拠の扱いと独立した認可・承認（#72 など）で制御する。この判断はそれを変えない。

## Issue の完了条件との対応

- 既存の対策・追加の効果・誤検知・未確認の事項: 上の「前提」「測定」「判断」と下の「限界」。
- 日本語 / 英語の注入・引用としての指示文・画像由来の文字・補助の文脈・全件 / 一部の隔離: 評価セットの群で検証した（隔離は採用しないが、比較のために実装して測った）。
- 隔離の理由・ID・本文から secret や閲覧不可の情報が漏れないこと: 実験の結果に残すのは根拠の ID と規則の名前だけ（製品の `_prompt_safe_warnings` と同じ）。製品の挙動は変えていない。閲覧不可の文書は検索の範囲で除かれてから検知するので、警告に閲覧不可の根拠の ID は出ない（今の経路のまま）。

## 限界

- 攻撃は canary を書かせる・偽の事実を答えさせる形だけ。回答の本文以外（引用の選び方・回答の拒否の誘導・長い文書の中に埋めた指示）は測っていない。
- モデルは DeepSeek の 2 つの名前（同じ提供元。別の系統かは未確認）。指示に従いやすいモデルでは警告で 0 件にならない可能性がある。モデルを変えるときは同じ実験を流す（`--repeats` を増やす）。
- 根拠は検索を通さずに直接渡した（検索・再ランク・CRAG の評価器・追加の検索は通らない）。CRAG の評価器にも同じ警告と不可信の区切りが渡ることはコードで確認したが、評価器の判定への影響は測っていない。
- 評価セットは 15 問で小さい。率は傾向として読む。
