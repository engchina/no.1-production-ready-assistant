# 全文検索が上限に達したときの補完

Oracle Text の式は既存の 24 語・3,800 文字の枠を維持する。質問に明示された識別子・版・日付・数値条件と項目名を優先し、型番の内部の数字を別の条件として重複配分しない。省略した語と実際の式は `text_search_tokenization_traces` に記録する。語の一致から回答の根拠が十分かを判定しない。

元の質問が上限に達した場合は、質問契約の元の要求 ID ごとに、要求の原文と共通の前置きで補う。検索範囲・分類・確認済み条件は主の検索と同じものを渡す。分割にモデルを使わず、補完検索では文書選択・画面目録・条の目録のモデル呼び出しを使わない。

追加の検索は `ExtraRetrievalBudget` の `query_overflow` から数え、業務ガイドと生成後の不足の補查が使う同じ回数の枠を消費する。`CoverageUsage` に検索文・時間・新たに採用した根拠数を記録し、後続の不足の補查でも同じ残りの枠を使う。既検索の原文と同じ検索は再実行せず、同じ分割文が複数の要求に対応するときは結果を再利用する。失敗も同じ実行内で再試行しない。

`generation_trace.query_overflow` の要求別の記録は次を区別する。

| status | 実行の事実 |
| --- | --- |
| `candidate_found` | 実行し、根拠レコードを取得した。回答の充足を意味しない |
| `no_candidates` | 実行したが、回答用の根拠レコードはなかった |
| `failed` / `reused_failed` | 実行が失敗した / 同じ失敗を再実行しなかった |
| `reused` / `already_searched` | 分割結果を再利用した / 主の検索か先行検索で同じ原文を実行済み |
| `unsearched_budget` / `unsearched_deadline` / `unsearched_evidence_budget` | 共有の回数 / 期限 / 追加根拠数の枠で未検索 |
| `unsearched_query_overflow` | 1 要求と共有条件だけでも保護した語が収まらず未検索 |
| `unsearched_tokenization_failed` | 語の抽出が失敗して未検索 |

既存の根拠を追い出す統合は採用せず、追加する根拠数にも既存の不足補查の上限を使う。新たに採用した ID は `added_chunk_ids` に記録する。

呼び出し元が検索文を明示する `caller_queries` では追加の分割を行わない（`skipped=caller_planned`）。一つの要求と共有条件の保護語だけで上限を超える場合は、条件の組み合わせを推測して検索しない。未検索は「資料に無い」と扱わない。

決定論テストは範囲・回数・期限・記録の契約を確かめるもので、検索品質を証明しない。実 Oracle と同一条件のモデル比較（既存の #2573 の比較基盤を使用）による Recall・呼び出し数・負荷・p95 の検証は別に行う。
