# 実行履歴（Run history）の型

> 3 製品（RAG・NL2SQL・Agent）の「実行履歴」（サイドナビの「AI 活用」の下。アイコン `History`）の一覧と詳細の正本（#1955）。
> 部品は `@production-ready/ui` の `RunHistoryTable` / `RunHistoryToolbar` / `RunStatusBadge` / `RunSummary` / `RunTimeline` / `RunDetailSection` / `RunDetailLayout`（design-system README §4「実行履歴」、components-reference「実行履歴」）。
> 一覧の基準（件数・ページ送り・ツールバー・読み込み中）は [page-archetypes.md](./page-archetypes.md)、絞り込みの部品は #1933（`FilterSelect`）、見え方（実行者・会話の持ち主）は #1954 と backend-standard.md「「AI 活用」の下の機能のデータの見え方」。

## 0. なぜ決めたか

3 製品の実行履歴は別々に作られ、見た目と使い方がそろっていなかった（2026-10-15 に Playwright で棚卸し。#1955 段 1 の PR に画面の画像と表）。

| | RAG（#1890） | NL2SQL（#1946） | Agent（#1897） |
|---|---|---|---|
| 一覧 → 詳細 | 全幅の詳細（`/history/<run_id>`） | 左の行リスト + 右の詳細のペイン（同じ画面） | 全幅の詳細（`?id=<run_id>`） |
| 一覧の形 | `DataTable`（質問・回答・検証・状態・所要時間・日時・利用者） | 手書きの行リスト（質問・日時・エンジン・所要時間・評価のバッジ） | `DataTable`（目標・利用者・きっかけ・状態・操作） |
| 状態の絞り込み | 欄の上にラベルのある「種類」の選択欄 + 状態の `ToggleChip` | 評価・安全性の選択欄 | 状態の `ToggleChip`（6 つ） |
| 詳細の構成 | 概要 → タブ（結果 / 処理の経過 / フィードバック） | 見出し → タブ（概要 / SQL） | 概要 → 段 → 承認 → ツール → 成果物 → イベント |
| 時間 | 段の表（`DataTable`） | 時間の内訳の数字 | 段ごとのバッジ |

業界の型（2026-10-15 に公式の文書で確認。確認できなかった点は「未確認」。出典の URL は段 1 の PR）:

|---|---|---|---|

## 1. 決めたこと（推奨で確定。2026-10-15）

| 項目 | 決定 | 採らなかった案と理由 |
|---|---|---|
| 一覧 → 詳細 | **一覧 → 全幅の詳細の画面**（URL で開ける。「一覧へ戻る」で絞り込み・ページ・選んだ行を保って戻る）。3 製品とも同じ。NL2SQL の分割ペインはやめる | **右の詳細のペイン / peek**（LangSmith・Langfuse・Datadog）: 長い回答・根拠・SQL・処理の経過を読むには幅が足りない（NL2SQL の 1280px で詳細のペインは約 560px）。375px では結局別の画面になる。**一覧の行の展開**（Carbon の expandable row）: 中身が大きく、表の高さが暴れる |
| 詳細の URL | 製品の画面の URL のまま、実行 ID で 1 対 1（Agent `?id=<run_id>`、RAG `/history/<run_id>`、NL2SQL は `?id=<run_id>` にする）。題名のリンクは `href` 付き（新しいタブで開ける） | URL の形を 3 製品で 1 つにする: 利用者に見えず、ルーターの作り直しの費用に見合わない |
| 一覧の列 | **質問（リンク）/ 対象 → 状態 → 種類 → 実行者 → 開始日時 → 所要時間 →（token / 費用）→（製品の列 2 つまで）→ 操作** | **状態を先頭**: 行の見出し（`rowHeader`）は題名で、page-archetypes §0-7 の「先頭セルの対象名のボタン」と、狭い画面で残す 1 列が題名になる。状態は 2 列目に固定して縦に見比べられる |
| 質問の列の名前 | 3 製品とも「質問」（root AGENTS.md「言語」）。Agent の依頼も「質問」 | 「目標」（Agent）: 3 製品で同じ機能の文言は同じにする |
| 時刻 | **絶対時刻**「2026/10/15 09:12」（詳細は秒まで）。`<time dateTime>` | 相対時刻（「3 分前」）: 監査の記録・ほかの画面の時刻と見比べる業務で、相対時刻は書き写せない |
| 状態 | 共通の 7 つ（待機中・実行中・応答待ち・完了・ブロック・失敗・停止）を `RunStatusBadge`（色 + 形の違うアイコン + 文言）。実行中もアイコンは回さない | 実行中のバッジに `Spinner`: 一覧に動くものが並ぶと読みにくく、5 秒ごとの再取得で十分に変わる。処理の経過の実行中の末端の段（子の段を持たない段）だけ `Spinner`（子の段を持つ実行中の段は `CirclePlay`。#3436） |
| 絞り込み | **検索（`SearchField`）→ 状態 → 種類 → 期間 → 実行者**。検索の右はすべて `FilterSelect`（#1933。「状態: すべて」の形）。条件はすぐ適用し、作業状態（URL か sessionStorage）に残す | 状態の `ToggleChip` の並び: Agent は 6 つで `FILTER_CHIP_MAX_OPTIONS`（5）を超え、3 製品で形が分かれる。**条件の保存（saved views）**: 3 製品の利用規模では要らない |
| 種類の既定 | **品質評価の実行を残す製品は「品質評価以外」**（Agent `GET /api/runs?kind=not_evaluation`、NL2SQL `GET /api/nl2sql/history?kind=not_evaluation`。#1986）。選択肢は「品質評価以外（既定）/ すべて / 各種類（… / 品質評価）」で、「すべて」か「品質評価」を選べば出る。件数（「全 N 件」）と「条件をクリア」はこの既定を基準にする（既定のままなら「全 N 件」は品質評価を除いた数、「条件をクリア」は出さない）。品質評価の実行しか無いときは、空の状態に隠している件数と出し方を出す（#1983。NL2SQL は絞り込みを出したまま表の空の状態に出す）。NL2SQL の品質評価の実行は、Agent の品質評価の Run が MCP で呼んだ SQL の生成と実行（サービストークンの claim `run_source` = `evaluation`。backend-standard.md「製品間の連携」。NL2SQL 自身の SQL 生成評価はジョブを作らない）。RAG は品質評価・MCP の実行を実行履歴に書かない（`RunRecorder` を渡さない）ので、既定は「すべて」のまま | 既定の「すべて」: 品質評価を 1 回流すと評価のケースの実行が数十件並び、利用者の実行が埋もれる。品質評価の実行を一覧から除く（別の画面だけで見る）: 評価の実行の処理の経過を同じ詳細で確かめられなくなる |
| 期間 | すべて / 過去 24 時間 / **過去 7 日（既定）** / 過去 30 日。既定は 3 製品で共通の `DEFAULT_RUN_PERIOD`（#3386）で、初期値・「条件をクリア」の戻り先・「既定と違う条件か」の基準にする（過去 7 日のままなら「条件をクリア」を出さず、「すべて」を選ぶと既定からの変更として数える）。選んだ期間は作業状態に残し、明示の「すべて」も再読込・戻る・進むで保つ。backend には `since`（ISO 8601、`runPeriodSince`）で渡し、backend の API の既定（`since` なし = 全期間）は変えない。件数は期間で絞っていれば既定の 7 日でも「N 件（全 M 件）」（M は期間を掛けない見える範囲の件数）。期間だけで絞って 0 件で、それより前の実行があるときは `RunHistoryPeriodEmptyState`（「過去 7 日の実行はありません」と「すべての期間を表示」） | 既定の「すべて」（#1955 の当初）: 一覧は直近の実行を確かめる場面が多く、全期間を毎回読むと古い実行に埋もれる。期間を隠して黙って絞る: 件数の「全 M 件」と期間の空の状態で、隠れている実行があることを伝える。任意の範囲（日付の欄 2 つ）: 一覧の 1 行に収まらない。要るなら段 2〜4 の後で足す |
| 件数・ページ送り | `ListToolbar` の `ListCount`（「全 N 件」「N 件（全 M 件）」）+ 表の直下の `OffsetPagination`（サーバーの offset 型、表示件数 10 / 25 / 50 / 100、既定 `DEFAULT_PAGE_SIZE` = 25。#1952）。新しい順 | カーソルの「さらに読み込む」: 総数とページ番号の入力が無く、監査で「何件目」を指せない |
| 行の操作 | `RowActionMenu` 1 つ（停止・承認など。再実行は置かない。#2343）。詳細の概要の `ObjectActionBar` と同じ定義 | 行の中のボタン: 行の高さと表の幅を取る |
| 詳細の構成 | **概要 → 処理の経過（タイムラインと、その後ろの畳んだ「処理の詳細」。#2325）→ 回答 → 根拠 / SQL / 検証 → フィードバック →（Agent の監査ログ）** を縦に 1 枚（`RunDetailLayout`） | **タブ**（RAG・NL2SQL の今の形）: 根拠・処理の経過が隠れ、ページ内検索・印刷・読み上げで届かない。長い Agent の処理の経過は、段の中身を畳んで短くする |
| 処理の経過 | `RunTimeline`: 1 行 = 1 段（ツールの呼び出しは字下げ）、状態のアイコン・名前・所要時間（文字）と、全体の中の位置と長さの線（ウォーターフォール）。中身（引数と結果・SQL・エラー）は行を開く。失敗した段は最初から開く | 段の表（RAG の今の形）: 時間の比較が数字の読み比べになる。**グラフ・ズーム**（Langfuse・OpenAI）: 3 製品の段は数〜数十で、1 画面に収まる |
| 狭い画面（375px） | 一覧は表のまま 2 列（題名・操作）にし、状態・開始日時・所要時間・種類・実行者を題名の下の 1 行にまとめる（container query 56rem）。処理の経過は線を隠す（40rem）。概要の事実は 1 段 | カードのリストに作り替える: 表と別の DOM を持つと、e2e・読み上げの規則が 2 つになる |

375px（表の置き場所が 56rem 未満）:

```text
│ 質問                                   │    │
│ 先月の売上は？（2 行まで）             │ ⋯  │
│ 販売分析                               │    │
│ [✓ 完了] 2026/10/15 09:12  3.2 秒  チャット │    │
```

- **列**（`RunHistoryTable`）: 質問（`RowTitleButton`。`href` 付きのリンク、2 行で切り詰め、全文は Tooltip と詳細。下に対象の名前）/ 状態 / 種類（1 種類しかない一覧は出さない）/ 実行者（他の人の実行が見える利用者だけ。自分は「自分」）/ 開始日時 / 所要時間（右寄せ・等幅数字、実行中・記録なしは「—」）/ token / 費用（記録している製品だけ。Agent・RAG・NL2SQL は見出し「token」で合計の token を右寄せ・桁区切り。記録なしは「—」で 0 にしない。利用量を数える製品（RAG・NL2SQL）は詳細の概要と同じ注記を `usage.note` で渡し（共通の `runListUsage`）、計測していない実行は「未計測」、一部の呼び出しの利用量が無い実行は数の下に「一部計測」、LLM を呼ばなかった実行は実測の「0 token」。一覧の API は合計と計測の状態だけを返す。#3466・#3543。狭い画面では出さない）/ 製品の列（2 つまで。RAG の回答の対応、NL2SQL の行数など。狭い画面では出さない）/ 操作。
- **状態**: 製品の状態を共通の 7 つに写す（下の表）。製品に固有の言い方は文言だけを上書きする（Agent の waiting →「承認待ち」）。
- **絞り込み**: `RunHistoryToolbar`（`ListToolbar` を包み、並び・既定・「条件をクリア」・3 つ以上のシートを固定する）。左に検索欄（質問・実行 ID。debounce・IME は `SearchField`）、その右に `FilterSelect` を「状態 → 種類 → 期間 → 実行者」の順（無い条件は飛ばす）。選択肢は共通の値（`RUN_PERIODS` / `RUN_EXECUTOR_FILTERS` と各製品の状態・種類）、既定は「すべて」（Agent・NL2SQL の種類だけ「品質評価以外」。`RunHistoryToolbar` の `kind.defaultValue`。既定の文言が長いので欄は `md`。#1983・#1986。期間だけ `DEFAULT_RUN_PERIOD` の過去 7 日。#3386）。条件を変えたら 1 ページ目へ戻す。0 件は「条件に一致する実行がありません」と条件のクリア（#1933）、期間だけで絞って 0 件でそれより前の実行があるときは `RunHistoryPeriodEmptyState`（期間を「すべて」にする操作。#3386）、そもそも 0 件は `EmptyState`（「まだ実行がありません」と、実行を始める画面の案内）。
- **件数・ページ**: 上の表のとおり。5 秒などの自動の再取得で行が変わってもページは戻さない（戻すのは条件を変えたときだけ）。
- **行**: 題名のリンク（Tab → Enter）が主な導線、行のクリックは補助（`onRowClick`）。詳細から戻ったら、開いていた行に `aria-current` と選択の面を付ける（`selectedRunId`）。
- **読み込み中**: 初回は `TimedLoadingState`（「実行履歴を読み込んでいます」+ 経過時間）+ `TableSkeleton`（列は 4）。再取得は前の一覧を出したまま、`PageHeader` の「最新情報を取得」の `loading`。
- **失敗**: 一覧の位置に `ApiErrorBanner`（再試行付き）。前の一覧があれば出したまま。

### 状態の写し方

| 共通の状態 | 文言（既定） | 色 / アイコン | RAG | NL2SQL | Agent |
|---|---|---|---|---|---|
| `queued` | 待機中 | neutral / `Clock` | — | — | `queued` |
| `running` | 実行中 | info / `CirclePlay` | （実行中の記録があれば） | — | `running` |
| `waiting` | 応答待ち | warning / `CirclePause` | — | — | `waiting_approval`（「承認待ち」）・確認の回答待ち |
| `succeeded` | 完了 | success / `CircleCheck` | `success` | SQL を実行・生成できた | `completed` |
| `blocked` | ブロック | warning / `ShieldAlert` | `blocked`（ガードレール） | 安全性の判定で止めた | — |
| `failed` | 失敗 | danger / `CircleX` | `error` | 生成・実行の失敗 | `failed` |
| `cancelled` | 停止 | neutral / `CircleSlash` | 利用者が止めた | 利用者が止めた | `cancelled` |

回答の質（RAG の回答の対応・検証、NL2SQL の評価）は状態に混ぜず、詳細の概要のバッジ（`badges`）と、要るなら一覧の製品の列に出す。

## 3. 詳細

```text
┌ PageHeader「実行の詳細」  ← 一覧へ戻る ───────────────────── [最新情報を取得] ┐
┌ 概要  [✓ 完了] [根拠あり]           [会話を開く / 〜で開く] [その他の操作 ▾] ┐
│ （失敗・ブロックの理由の Banner）                                            │
│ 質問                                                                         │
│ 先月の売上を地域別に教えて                                                   │
│ 開始日時 2026/10/15 09:12:05  所要時間 3.2 秒  種類 チャット  実行者 管理者  │
│ 会話の持ち主 山田  業務プロファイル 販売分析  モデル openai.gpt-oss-120b      │
│ token 2,000  費用 $0.01  （製品の事実）  実行 ID run-123                     │
└─────────────────────────────────────────────────────────────────────────────┘
┌ 回答 ───────────────────────────────────────────────────────────────────────┐
┌ 処理の経過  5 ステップ・合計 3.2 秒 ─────────────────────────────────────────┐
│ ✓ 質問を分類        ▕██            ▏ 0.4 秒                                  │
│ ✓ SQL を生成   ›    ▕  ████████    ▏ 2.1 秒                                  │
│ ✗ SQL を実行   ⌄    ▕          ██  ▏ 失敗 · 0.3 秒                           │
│     ORA-00942: 表またはビューが存在しません                                   │
│ › 処理の詳細（既定で閉じる）                                                  │
┌ 根拠 / SQL と結果 / 検証 / 成果物（製品の節）──────────────────────────────────┐
┌ フィードバック ─────────────────────────────────────────────────────────────┐
┌ › 監査ログ（Agent。既定で閉じる）─────────────────────────────────────────────┐
```

- **戻る**: `PageHeader` の `back`「一覧へ戻る」（読み上げ名「実行履歴の一覧へ戻る」）。戻ると絞り込み・ページ・スクロールを保つ（workspace-state.md）。ブラウザの戻るも同じ。対象が無い・見えない（404 / 403）は「この実行は見つかりません」と一覧へ戻る案内（別の実行に置き換えない）。

## 実測 trace と処理の経過

質問の入口（Agent チャット、RAG チャット・検索、NL2SQL チャット・SQL 生成・DB 管理チャット）は `ChatProgress` を使い、結果の上に処理の経過を置く。処理中は開き、成功したら要約を閉じる。停止と失敗は別の状態で、停止操作・失敗の案内・再試行の操作は経過を閉じても確認できる場所に残す。

**処理の経過は trace（span の木）の投影で、記録は 1 つだけにする（#3226。業界の作り: OpenTelemetry GenAI・Langfuse・LangSmith・Arize Phoenix と同じ）。** 処理の経過の行は span で、入れ子は span の親子、時刻と所要時間は span の実測。span は共通の span の表（`PLATFORM_TRACE_SPANS`）にあり、画面は製品の記録の trace id で読む（実行中は読み直す。`useTraceProgressSnapshot`）。実行中も木が増えていく（開始した span は実行中、終わった span は所要時間つき）。Agent が MCP で呼んだ RAG / NL2SQL の span は、Agent の木の `mcp.request` の下に出る（見えるのは、その実行の利用者と system_admin）。最終の状態（完了・失敗・停止）は製品の記録で決め、表に書けなかった span があれば「一部の処理だけを記録しています。」を出す。「トレースの詳細」のような 2 つ目の表示は置かない。実行の全体の span（root）は行にせず、見出しの要約（「N ステップ・合計 M 秒」）が全体を表す。trace ID は業務の Run ID と区別し、「処理の詳細」に Trace ID とコピーのボタンで出す（ID の文字列だけを折り返し、ボタンを同じ行に置く）。時刻がある並列処理の総時間は最初の開始から最後の終了までとし、呼び出し秒を足し合わせない。欠落・切り詰め・未計測は成功と見なさない。利用量の不明を 0 と表示しない。行を開いたときの技術の値は allowlist の属性だけで、識別子（`Span name`・モデル・ツール など）は属性名のまま、利用量（`gen_ai.usage.*`）と Agent のモデルの呼び出しの入力の文脈の記録（`pr.context.*`。見積もり・予算・圧縮の前後・指示とツール定義の指紋。#2583）は日本語の見出しで出す（`traceSpanFields`。記録の無い値は行にしない）。キャッシュから読んだ入力は、プロバイダが返さなければ「不明」と出して 0 と区別する（#3409）。

行の名前の規則は共通の部品（`platform/packages/ui` の `labelChatProgressSteps` と `traceSpanDisplayName`）の 1 か所に置き、3 製品の 10 画面（チャット・RAG 検索・SQL 生成・DB 管理チャット・実行の詳細・回答の記録）で同じにする（#3214・#3219・#3226）。工程の span（表示用のデータの `kind` を持つ span）は製品の工程の定義（`ChatProgressStepDefinitions`。処理の経過の段の名前・補足・計測値）で名前を付ける。それ以外は、段（`pr.stage`）は製品の段の名前、`gen_ai.*`・MCP・Select AI・HTTP の呼び出しは日本語の名前（「モデルの呼び出し」「埋め込みの作成」「並べ替え（rerank）」「ツールの実行」「MCP の呼び出し」など）にモデル名・ツール名を添え、2 回目以降の試行は回数を付ける。それでも無ければ span の名前で出す。文言は製品の root で `TraceDetailsLabelsProvider` に 1 回だけ渡し、画面ごとに渡さない。

行を開いた詳細は、工程の詳細（span の表示用のデータ）と、span の名前・段（`pr.stage`）・モデル・ツール・試行・provider の利用量・安全なエラーの種類に限る。質問・SQL・認証・結果の行は telemetry の属性から表示しない。深い階層は余白を3段で止め、375px でも名前と詳細を読める幅を残す。孤立親・cycle・重複 ID の記録でも無限に描画せず、親の無い span は最上位に出す。

span の無い古い形式の記録（段だけのイベント・工程の秒だけの記録）は表示しない。処理の経過の位置に「この実行は古い形式の記録のため、処理の経過を表示できません。」と出し、空白にしない（未リリースのため後方互換は持たない）。

## 呼び出し時点の入力・結果・Schema（#3889）

3 製品のモデル呼び出しとツール実行の詳細は、共有の `RunStepDetailsView` で「概要 / 入力 / 結果 / Schema / 計時」に分けて表示する。入力・結果・Schema は実行時の snapshot とし、現在の設定や後続の応答から再構成しない。記録が無い旧実行・未受信の結果・Schema を渡さない呼び出しは「記録されていません」と表示する。権限で伏せた内容と、長さの上限で切った内容は別の文言で示す。

本文は span の外部 export や `PLATFORM_TRACE_SPANS` の属性に入れず、製品の詳細記録に保存する。本文は項目ごとに最大 64,000 文字で、secret を伏せてから切る。画像の実体・HTTP の認証 header は記録しない。モデルが公開しない内部の推論は再構成しない。

RAG のモデル入力は未引用の資料や目録も含む。参照全体の文書範囲を証明できない新しい汎用 snapshot は system_admin に限って公開する。通常利用者には階層・時刻・状態・モデル利用量を引き続き表示する。Agent の保存した根拠の現在の閲覧権限が失われている場合は、混在した呼び出し snapshot をまとめて伏せる。閲覧用の写しだけを変更し、保存した記録は上書きしない。

### 軌跡の調査（#3891）

- 3 製品のチャット・実行履歴の `RunTimeline` は「軌跡を調べる」から共有 `TraceExplorer` を開く。通常の経過の表示を既定とし、戻ると開いたボタンへフォーカスを戻す。
- 上から、実測の時間の概観（工程 / モデル / ツール）、検索と種類・状態の絞り込み、階層 / 開始時刻順、呼び出しの一覧と選択した詳細の順。既存の共有部品・色・書体・寸法を使う。モデル・ツールの分類には翻訳した名前ではなく、記録された operation 名を使う。
- 概観は実際の開始・終了時刻だけで配置する。並列の呼び出しを足し合わせない。開始時刻の無い記録は概観から外し、一覧と案内を残す。終了時刻の無い呼び出しは開始位置だけとし、端末時計から完了時間を補わない。
- 概観は全体を保ち、検索は一覧を絞る。検索対象は現在の権限で提供された名前・ID・操作名・詳細と、記録済み/切り詰め済みの snapshot 本文。伏せられた snapshot の本文は索引へ入れない。検索と絞り込みの一致がゼロなら条件を戻す操作を出す。
- 詳細は選択した 1 件だけを描く。一覧の選択位置と概観の印を同期し、親の記録があるときは経路も出す。「概要 / 入力 / 思考 / 結果 / Schema」を使い、時刻はタブの外にまとめ、前後への操作、ID のコピー、状態と所要時間を持つ。呼び出し間では選んだ内容のタブを保つ。
- 置き場所が広いと一覧と詳細を 2 列にし、詳細を追従させる。狭い場所では一覧/詳細を切り替え、詳細の表示中は概観と絞り込みを畳む。「一覧に戻る」で選択した行へフォーカスを返す。キーボードの上下で一覧の行へ移動し、Enter / Space で選択する。深い木は共有 viewport の中で横に移動する。
- 長い一覧は 50 件ずつ追加表示し、全記録を検索できる。本文は既存の上限とスクロール領域を使う。探索画面を開いても runtime、モデルへの指示、保存の契約、権限は変えない。
- 設計の参照: [DeepSeek Harness trajectory](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-trajectory/README.md) の概観・ledger・inspector、[Langfuse trace view](https://langfuse.com/changelog/2025-03-19-new-trace-view) の階層/時刻順と検索。共通の情報設計を採用し、他製品の runtime の内部状態を推測しない。

軌跡の調査の時間条と呼び出し一覧は、処理の経過と同じ文字の大きさ・時間条の高さ・丸み・状態色を共有する。時間の概観の区分（工程 / モデル / ツール）と選択操作は保持する。選択した区間は上方の時間の概観で輪郭を出し、重なった区間より前面に表示する。

チャットの対象（RAG の検索・回答プロファイル、NL2SQL の業務プロファイル、Agent の業務 Agent）は `ChatLayout.targetSelector` を通じて、履歴の開閉・会話名・新しい会話と同じツールバーに置く。独立した選択カードは出さない。`SearchableSelectField` の compact 表示は選択値を 1 行で省略し、全文は title、欄の意味と必須は読み上げ名に残す。未選択時は必須の印を出し送信を抑止する。候補の検索・キーボード操作・切り替え時の会話の範囲・読込と失敗の扱いは通常の欄と同じとする。狭い幅では同じツールバー内で会話名と選択を縦に並べる。

### 経過と軌跡の共通の表示契約（#3918）

- 経過は処理の摘要、軌跡は完全な詳細。両方の階層順は `traceOrderedSteps` を使い、名前・状態・所要時間・結果の摘要を同じ値と書式で出す。時刻順のタブを利用者が選んだときだけ別の並びにする。
- 経過の閉じた行は名前 → 状態・所要時間 → 結果の摘要。開くと目的・条件・影響・結果と必要な資料を出す。技術属性やモデルの入出力のタブは経過に重ねない。
- 軌跡の詳細は名前・状態・所要時間・コピーできる Span ID → 処理内容と資料 → 開始・終了時刻 → 技術属性。結果のフィールドは処理内容の末尾に置き、資料の行を続ける。各ブロックは共有の `gap-2` で区切る。
- 技術属性は共通の span 投影で型を付け、経過では省略する。表示文言を見て削除したり、元の span や記録を変更したりしない。属性の元の名前・ID は等幅で軌跡に残す。未知の操作も共通 i18n の「処理を実行する」を主表示にし、内部名は独立したフィールドにする。
- 時刻はシステムの表示の時間帯で年月日・24 時間の時分秒と時間帯を明示。表示の短さと精度を分け、元の ISO は `time.dateTime` / title とコピー操作に保持する。所要時間は同じ人向けの単位を使う。
- 行の文字・状態アイコン・フィールドの表示とラベルの揃え・コピーは共通部品と token。3 製品の desktop / 375px の Playwright で順序・階層・共通の値と computed style、元の ISO のコピーを確認し、light / dark のスクリーンショットを確認する。
