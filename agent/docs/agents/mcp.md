# Agent の MCP 境界

> agent/AGENTS.md から移した詳細（#2276）。agent/AGENTS.md の規則と同じ強さで守る。規則を変えるときはこのファイルを直し、AGENTS.md には規則の要約と案内だけを書く。

## MCP 境界

- **Agent は外部の MCP クライアントに業務 Agent へのチャットを公開する**（`POST /api/mcp`。`features/agent/mcp_server.py`。#1874）。認証は共通の API キー（使える製品に `agent`）だけで、キーを発行した利用者の権限・対象範囲で判定し、キーに業務 Agent の範囲があればさらに絞る（範囲の外は 403）。ツールは `agent_list` / `agent_chat` / `agent_get_run` / `agent_answer_confirmation` / `agent_cancel_run` / `agent_get_run_observation` / `agent_skill_export`（契約は `platform/contracts/mcp/agent-tools.json`）。
  - MCP から作った Run（`metadata.source=mcp`・キーの ID と名前）は、無人の実行と同じく承認の要るツールを呼ばない（`mcp.approval_required`。#1813 と同じ流れ）。回答前の確認（#1839）は構造化して返し、`agent_answer_confirmation` で答える。
  - 完了した回答には回答の注意書き（設定は製品ごと。#2405・#2449）を `notice` で返す（API キーの呼び出しだけ）。RAG / NL2SQL をサービストークンで呼んだ結果には注意書きが無い（呼び先が API キーの呼び出しにだけ返す）ので、Agent の回答の末尾には Agent が最終の検証の後に付ける 1 つだけが出る（回答の成果物の `notice`。本文の `text` とは別で、会話の履歴・最終の検証には入れない）。
  - Run・会話の見え方は画面と同じ（キーの持ち主が system_admin なら他の利用者の Run を読めるが、会話の続きと確認への答えは持ち主だけで 403 の `OTHERS_CONTENT_FORBIDDEN`。#3244）。
  - Run の出力（`RunOutput`。`agent_chat` / `agent_get_run` / `agent_answer_confirmation`。`schema_version` 4。#3240・#3321）の名前と語彙は RAG の公開の契約にそろえる: `outcome` は `rag_search.outcome` と同じ 6 つの値（成果物 `answer` の `outcome.value`。完了した Run だけ、ほかは null）、`sources[].document_id` / `chunk_id` は RAG の根拠と同じ名前（会話の添付の根拠は null）、`sources[].cited` は回答で引用した根拠か。`agent_get_run` は見る人の今の権限で見られない根拠を `sources` から除き、数を `withheld_evidence_count` に返す（#3252）。根拠の本文（`sources[].excerpt`）は RAG の根拠と同じ規則（platform の `pr_backend_core.source_text`。#3321）: 既定で全文を、応答の全体の予算に根拠の順で入れ、入らない根拠は本文を省いて `text_omitted`（数は `sources_text_omitted`）、1 件の上限を超える根拠だけ質問に当たる部分を中心に文・段落（表は見出しの行を残して行）の境界で切って `truncated`・`excerpt_range`・`header_range`・`next_offset`（位置は RAG の chunk の本文の位置。続きは RAG の `rag_read_source`）。RAG が省いた・切った根拠はその印と位置をそのまま返す。判断の道筋（`outcome` の `basis` / `signals`）・スコアは出さない。一致は `tests/test_mcp_contract.py` が `rag-tools.json` と比べて確かめる。すべての出力に `schema_version` を持たせる（`agent_list` / `agent_skill_export` は 1）。
  - `agent_cancel_run`（#3240）は画面の `POST /runs/{id}/cancel` と同じ判定（`_readable_run`。実行した利用者・会話の持ち主・system_admin〔#3244 の運用の操作〕、キーの業務 Agent の範囲、capability は `agent_chat` と同じ）で、同じ `cancel_run` を呼ぶ（取消の伝わり方は #2691 のまま）。冪等で、終わった Run はツールのエラーにせず `result`（`cancelled` / `already_cancelled` / `already_finished`）で返す（画面の REST の 409 は変えない）。取消のイベントに操作した人（`cancelled_by`）と入口（`via=mcp`・`api_key_id`）を残す。Run を作らないのでキーの Run の数の上限に数えない（1 分あたりの呼び出しには数える）。annotations は `destructiveHint` / `idempotentHint`（`McpTool.destructive` / `idempotent`）。
  - `agent_get_run_observation`（#3240）は評価・監査の機械（suite の adapter など）が Run の観測を公開の契約で読むツール（`RunObservation`。`schema_version` 1。読み取り専用で `tools/list` に出す）。観測は Run が保存した記録だけから作り（`features/agent/run_observation.py`。RAG / NL2SQL に新しく読みに行かない）、読める人・範囲・capability は `agent_get_run` と同じ（`_readable_run`・`_READ`。ID を知っていても読めない）。出すのは Run の情報（`agent_version`・`trace_id`・`validation_status`・時刻・`outcome`）、`usage`（`gen_ai.usage.*` の名前）、`tool_calls[]`（Run の順・200 件まで・全件の数 `tool_call_total`。状態〔`approval_skipped` は承認が要るため呼ばなかった〕・失敗の分類 `error_code`〔分類の形でない値は `tool_error`〕・`evidence_count`・`include_superseded`・NL2SQL の `job_status` / `row_count` / `rows_truncated`・RAG の根拠のツールの縮退〔`degraded_steps` の種類と回数・根拠 0 件の段 `zero_evidence_stage`。#3546〕）、`evidence[]`（RAG の根拠のツールの `evidence` と、読み取りのツール〔`rag_read_source` / `rag_read_document` / `rag_read_section`〕で読んだ chunk。`(document_id, chunk_id)` で重複を除いて初めて現れた順を `rank`、引用は成果物「回答の根拠」の `cited` / `answer_use`、場所は RAG の `EvidenceLocator` と同じ名前〔`bbox` は出さない〕、表の行・列の対応の検査が本文を読めるかは RAG の `table_binding`〔#3546〕。会話の添付の根拠は含めない）。根拠の本文（`text`）は生成に渡した本文そのもの（同じ chunk に別の呼び出しが渡した本文は改行でつなぐ。rag の評価の CLI と同じ規則）で、platform の `page_source_texts`（#3321）で件数（既定 20・最大 100）と 1 ページの合計の予算に分け、1 件で予算を超える根拠は本文を省いて `text_omitted`。`cursor` は Run の ID と根拠の全件の中の位置に結んだ不透明な文字列（別の Run の・壊れた `cursor` は `INVALID_CURSOR`）。根拠は呼ぶたびに見る人の今の権限で確かめ直し（#3252 の `evidence_access`。確かめられなければすべて伏せる）、見られない根拠を `evidence[]`・`evidence_count`・`evidence_total` から除いて `withheld_evidence_count` に数える。出さないもの（OWASP API3）: ツールの引数の本体・NL2SQL の SQL・行・列の名前・`profile_id`（設計の Q5）・RAG のスコア・`bbox`・`references`・エラーの文・`outcome` の `basis` / `signals`・Run の `metadata`・質問の文（`tests/test_run_observation.py` の canary で確かめる）。名前の一致は `tests/test_mcp_contract.py` が `rag-tools.json` と比べて確かめる。
  - 評価・監査の機械（製品横断の評価 `suite/evaluation` の Agent の adapter）は、Run のデータを公開の `agent_chat` / `agent_get_run` / `agent_answer_confirmation` / `agent_get_run_observation` / `agent_cancel_run` だけで読む（画面の API・Run の内部の記録・Agent のコードに依存しない。#3240）。回答の前の確認には `agent_answer_confirmation` で答える。業務 Agent の作成・公開の MCP のツールは持たない（設計の Q4。攻撃面を広げない）ので、公開済みの業務 Agent を ID で指定し、観測の `agent_version` を対象構成に記録する。時間切れの Run は `agent_cancel_run` で止め、`result` を記録する。知らない `schema_version` の出力は推測で読まずケースの失敗にし、`outcome` が null の完了の Run は評価の側で評価不能にする（Agent は旧形式の推定の材料〔`rag_search` の outcome など〕を出さない）。承認の要るツールを呼ばなかった Run（`skipped_approval_tools`・`tool_calls[].status=approval_skipped`）は評価でケースの失敗にする（設計の Q7）。MCP の出力の規則は、段 1 の合成の Run を本物の MCP の入口で読んだ共有の fixture（`platform/contracts/mcp/fixtures/agent-evaluation-baseline.json`。`tests/test_evaluation_baseline_observation.py`）で固め、suite の評価の基線（`suite/evaluation/tests/test_baseline.py`）がその公開の出力だけで採点する。観測・出力を変えたら `UPDATE_AGENT_EVALUATION_BASELINE=1` で fixture を書き直し、suite の基線の採点が変わらないことを確かめる。
  - キーごとの直近 24 時間の Run の数の上限（`PLATFORM_API_KEY_RUNS_PER_DAY`。超えたら 429 相当のツールのエラー）。1 分あたりの呼び出しの回数は共通の認証が数える。
  - RAG は Agent を呼ばない（Agent の MCP を呼ぶのは外部のクライアントだけ）。サービストークンでの Agent の MCP の呼び出しは持たない。
- **Agent → RAG / NL2SQL の依存は公開の契約だけ（#3240）。** 依存してよいのは、ツールの名前・inputSchema（既定・上限）・outputSchema・失敗の code（`rag-tools.json` の `errors`）・annotations、`platform/contracts/answer-passages/**`（段落の規則の事例と語彙）、platform の共通の規則（サービストークンの claim `purpose` など）。RAG の module・表・画面の API と、内部の既定値・根拠の ID の形・言語資源の語・段落の分け方の一致を前提にしない: 最終の検証は判定の `answer_range`（渡した回答の中の位置）で Agent の段落に結び付け（`answer_validation.align_claims`）、件数の既定は契約の `default`、回答が省いて書いた根拠の ID は渡された ID の値で照合し、RAG の回答の末尾の節の見出しは共有の語彙（`unverified_section_titles`）から読む。契約に足りないものは、呼び先の出力と契約を版を上げて足す（写さない）。テストは共有の出力の例（`platform/contracts/mcp/fixtures/rag-tool-outputs.json`。fake の RAG の既定の出力）と契約で動かし、`tests/test_rag_contract_usage.py`（名前・code・語・出力の例が契約にある）と `tests/test_product_boundaries.py`（RAG・NL2SQL・suite の module・ディレクトリ・表・画面の API に依存しない）が確かめる。
- RAG / NL2SQL / 外部 MCP は「MCP 接続」1 つの仕組みで管理する（旧「外部 RAG」「外部 NL2SQL」「外部 MCP」は持たない）。RAG / NL2SQL は標準の接続 `rag` / `nl2sql`（画面の名前は「ナレッジ検索（RAG）」「データ問い合わせ（NL2SQL）」。認証はサービストークンで、削除・名前・認証方式の変更はできない）。URL は `AGENT_EXTERNAL_RAG_MCP_URL` / `AGENT_EXTERNAL_NL2SQL_MCP_URL` で、配備がこれを与えた接続は URL も変えられない（API は 400、`base_url_locked`）。空の構成（ローカルの開発・その製品を配備しない構成）だけ画面で URL を設定できる。外部の MCP は認証方式（なし / API キー / OAuth client credentials / サービストークン）を選んで追加する。
- MCP 接続のツールは、組み込み Runtime から `tool_registry.invoke`（`definition` / `handler` を渡す）を通してだけ呼ぶ（policy・masking・監査を再利用する）。承認の要否は MCP の `readOnlyHint` とツール権限（`<接続>__<ツール>` の名前）。ツールの表示名（`tools/list` の `title`、無ければ `annotations.title`）は Run の metadata `tool_titles` に残し、画面の処理の経過の段の名前にだけ使う（モデルには渡さない。RAG / NL2SQL / Agent の MCP は共通の `McpTool.title` で出す。#2324）。外部 API key・token を snapshot、API、ログ、Artifact に出さない。
  - `tools/call` の成功の結果は `parse_mcp_tool_result`（#2650）で受け取る: `structuredContent` があればそれを結果にし、構造化データを直列化しただけの text は二重に入れず、それ以外の説明文は `content_text` に残す（無ければ text を `content`）。image の content は画像（`ToolOutputWithImages`。モデルへの渡し方は runtime.md）にし、対象が利用者だけ（`annotations.audience` に assistant が無い）・使えない形式・大きすぎる画像はモデルに渡さず参照に理由を残す。ほかの種類（音声・resource など）は `content_omitted` に種類と数だけを残す。
  - 例外は画面の操作の「RAG の図の根拠を開く」（`GET /api/runs/{run_id}/figure-url`）と「根拠の原文のプレビュー」（`GET /api/runs/{run_id}/source-preview`。#2389）だけで、Run のツール呼び出しではないため `tool_registry` を通さず、**画面を見ている利用者**を `sub`・`purpose=figure_url` / `source_preview` にしたサービストークンで RAG の `rag_read_source`（`include_image_url` / `include_preview`）を呼び、返った短命の URL を保存しない（`features/agent/rag_figures.py`）。
- サービストークンは呼び出しごとの `issue_service_token`（`sub` = Run の利用者 `RunState.created_by_user_uuid`、画面の単発の操作はログイン中の利用者。`aud` = 接続の audience）。承認後の実行も承認者ではなく Run の利用者で呼ぶ。利用者の無い呼び出しは `mcp.user_required` で失敗し、別の主体に置き換えない（#3251）。サービスの主体で呼んでよい入口は無く、将来要るなら `sub` を黙って替えず、呼び先に見える別の主体（RFC 8693 の `act` など）として足す。業務 Agent にデータの範囲があれば、その接続の範囲の ID を claim `profile_ids` に入れ、呼び先でも強制させる（#1379。範囲なしなら付けない）。
- Run の取消は実行中の MCP の呼び出しも打ち切る（#2691。手順と読み取り専用のツールは接続を切り、書き込みのツールは送った後は結果を待つ。詳細は runtime.md）。呼び先（RAG / NL2SQL）は切断で読み取り専用のツールの処理を止める（`pr_backend_core.mcp`）。NL2SQL のジョブ（呼び先の worker で動く）は切断では止まらないので、Run が始めてまだ終わっていないジョブに Control Plane が `nl2sql_cancel_job` を送る（#3318。runtime.md）。
- 再試行は、送信前の失敗と 429 / 503 は全メッセージ、502 / 504 は手順と読み取り専用（`readOnlyHint`。注釈を信頼する接続だけ。#2595）のツールだけで、書き込みのツールと注釈を信頼しない接続のツールは呼び先に届いた後の失敗では再送しない。待ちは backoff + jitter（`Retry-After` に従う）、呼び出し全体は接続の timeout に収める（docs/agent-control-plane-design.md §4.1）。
